R:R Ratio

R:R 1:2.5 means: for every $1 you risk (entry → SL), you stand to gain $2.50 (entry → TP1). Minimum recommended: 2:1. Below 1.5:1 is not worth the risk.

DCA (Dollar-Cost Average)

Entering in two tranches at different prices to get a lower average entry. First entry at the current level, second (DCA) entry lower if price dips. Risk is 2% with DCA vs 1% for a single entry.

⚠ Warnings Explained
⚠ ATR Risk

ATR = Average True Range — the typical candle-to-candle price movement. If your SL is inside the ATR noise (< 1× ATR from entry), normal price fluctuation may stop you out before the trade has a chance to work. Move the SL further away or skip the trade.

⚠ Portfolio Correlation

You already have open positions in the same sector and same direction. If BTC dumps or the sector rotates, all those positions move against you at the same time. Consider reducing size or waiting for one to close first.

⚠ Candle-Close Stop Loss

This SL only triggers when a full candle closes below/above the level — not on a wick touch. It's more forgiving of noise, but Bitget cannot automate this. You must watch the chart and close manually when the candle closes through the level.

⚠ Personal Pattern Warnings

These are based on your own trade history — recurring situations where you specifically tend to lose. Not generic advice. If it says "Friday trades lose" that means YOUR Fridays, not the market in general.

AI Architecture — Pipeline & Cascade
How models are routed and what runs when
7-Agent Pipeline (Trade Analysis)
Each agent has one responsibility, returns a typed contract, and can be tested independently. Data fans in once, indicators compute deterministically, then a single Sonnet call assembles the verdict. Failures at any stage return empty defaults instead of crashing the pipeline.
1. DataCollector → parallel fetch from 15 sources (no AI) 2. DataInterpreter → indicators + S/R + confluence (no AI — pure math) 3. MarketSentiment → macro verdict + crowd contra (Haiku) 4. DataReviewer → quality gate + backtest context (Haiku) 5. RiskManagement → Kelly sizing + correlation (no AI — math) 6. TradePrep → final score + SL/TP + multi-TP (Sonnet 4.6 ★ / Opus 4.7 ‡) 7. TradeMonitor → open-position management (Haiku, every 10 min)
★ Sonnet 4.6 for the user-facing Call Analyzer + Scanner Stage 3b. Uses prompt caching (ephemeral, ≥1024-token stable prefix) — measured 74% hit rate within a single scan batch.
‡ Opus 4.7 swapped in for the Futures-AI consensus gate only (the real-money second-opinion). Sub-agents 3+4 stay on Haiku so cost stays bounded — only TradePrep gets upgraded. Env: FUTURES_AI_CONSENSUS_MODEL=opus.
5-Provider Fallback Cascade
When Anthropic returns an APIError (rate limit / outage / credit depleted), ai_client.send() walks this cascade sequentially. Each entry is skipped if it's in cooldown. All modules get fallback transparently — no per-module code changes.

Consensus Gate — Opus 4.7 + Overrides + Multi-TP
The real-money second-opinion that sits between scanner and Bitget
Opus Can Override Scanner Targets
When the consensus model (Opus 4.7) approves a scanner setup, it can also propose its OWN entry / SL / TP-ladder. The auto-trader uses these overrides instead of the scanner's targets when they pass safety validation. All overrides are persisted to futures_ai_log for hindsight cohort analysis.
Field Accept rule Reject reason
EntryDrift < 2% from scanner entryLarge drift = likely model hallucination
SLONLY tighter (closer to entry)Loosening SL would silently increase risk
TP ladder≥3 levels, strictly monotonic, first TP past entryOtherwise fall back to scanner's tp1/tp2
Multi-TP Ladder Splits
When Opus emits 3-7 TPs, the system applies the matching split. Front-loaded — first two TPs always take the largest share, runner trims to single digits.

Notional-Aware TP Count Clamping
Bitget's min order size (~$5 USDT) means a 5% TP slice can't fill on small positions. The system caps Opus's ideal count to what notional supports — smallest slice must always stay ≥ FUTURES_AI_MIN_TP_SLICE_USDT ($5 default).

Shadow Logs — Every Consensus Event Snapshots the Full Setup
Every consensus_rejected / consensus_approved / consensus_error event in futures_ai_log now embeds the complete scanner setup (entry, SL, TP1-7, scanner_score, ai_score, archetype, confluence, bear_phase, PO3 fields, rationale). This means a hindsight pass on rejected cohorts no longer needs to join against analyzed_calls (which dedups setups within ~30 min of each other and loses per-rejection state).

What it is
GOSH.AI is a hybrid intelligence layer (their tagline: "infinite context, any model, any scale · built around data, not models") that produces on-chain code via a DAO-governed workflow. It is not a self-trading on-chain agent — the agent runtime itself is off-chain (Rust), but it WRITES code that lives on the Acki Nacki / GOSH chain and gets reviewed + voted on by a DAO before being merged.

Workflow: upload Spec.md → bot creates a DAO + repository on chain → LLM proposes file changes as DAO proposals → DAO votes → accepted changes persist as immutable, timestamped on-chain commits. Currently supports asynchronous Solidity only.

Relevance to our DODEX integration
GOSH.AI does not change our integration plan. Our DODEX wiring is a Python client to the TVM-SDK Node sidecar reading DEX state and submitting orders — no AI code-generation step needed. However:
  • If we ever want to deploy custom on-chain trading logic (e.g. a Solidity contract that manages multi-leg orders, hedging splits, or programmable take-profits on chain), GOSH.AI is the path that comes with DAO-governed review baked in.
  • The gosh.agent + gosh.memory stack is structurally similar to our own auto_ai self-learning ladder (off-chain agent + persistent memory + LLM orchestrator) — worth watching as a reference design.
  • Same team as the chain itself = closer alignment with Acki Nacki's Solidity dialect and execution model than third-party Solidity tooling would offer.
Action: none required. Watch for gosh.common activity (the most-active repo) as a signal that the runtime is preparing GA. Re-evaluate after DODEX Phase-2 ships if we need on-chain trade-logic surface area.
